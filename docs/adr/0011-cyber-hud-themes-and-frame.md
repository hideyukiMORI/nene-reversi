# ADR 0011 — サイバー HUD: Gambit の B 案の画面、12 テーマ（黒石は暗いほう）、罫線は幅を測ってから使う

- 状態: 受理
- 日付: 2026-10-26
- Issue: #11
- 影響する規則: ARC-001 / ARC-011 / SWF-014 / FR-10 / FR-12 / FR-13 / FR-15 / FR-16
- 置き換えるもの: ADR 0007 の決定 1（画面の文字は ASCII だけ）のうち枠と棒グラフ、決定 4（配置）・5（HUD）・6（1 テーマ）

## 文脈

施主の決定: 画面は NeNe Gambit と同じ形（Q3・FR-16 の B 案の罫線の枠・2 段の配置・終局後の秒読み・罫線が 2 桁で描かれる端末では ASCII の枠へ自動で落とす）、
12 テーマは Gambit の 12 種類を引き継ぎ盤と石の色をリバーシ用に足す（Q8）、キーは `q` と `t` だけ（Q9）、HUD に石の数（Q6）。

Gambit は同じ画面を同じ規約で作っている（Gambit ADR 0007・0008）。画面の部品は自分たちのコードとして移植してよい（ADR 0003）。

Gambit の 12 テーマの配色をそのまま当てて計算した（2026-10-26）:

- 石（駒の 2 色）は 12 テーマとも 2 色の升に対して 3:1 以上、白黒の石どうしは明るさで 2.2:1 以上
- 直前の手の `[ ]` を強調の色で描くと、PAPER の暗い升の上だけ 3.8:1 で 4.5:1 に届かない
- Gambit の PAPER は紙の地に合わせて白の駒を墨色（#1A1714）・黒の駒を赤（#9E1B30）にしている。そのまま当てると**白石が黒く見える**（実機の画面写真で確かめた）

## 決定

1. **画面は Gambit の B 案**: 上端の題の帯（題・局の番号・シード・色の方式）、左に盤、右に罫線の枠の HUD、盤の下に COMMS の 2 行（中身は次の Issue）、
   下端のキーの帯（`[q] QUIT  [t] THEME: <名前>  │  LAST <直前の手>`）。部品（`Panel`・`FrameGlyphs`・`FrameStyle`・`Segment`・`Fraction`・`ScreenChrome`・`HudSections`）は
   Gambit のコミット 64b82ec から移植した
2. **HUD は MATCH（局・黒白の性格・手番と手数）・DISCS（いまの石の数の棒・Q6）・SCORE（通算の棒）・LOG（黒白 1 手ずつの行・次に打つ側にカーソル）・
   RESULT（勝敗と石の数・理由 `BOARD FULL` / `NO MOVES LEFT`・次の局までの秒読み）**。縮小版は MATCH を 5 行に詰め、LOG か RESULT の片方を出す
3. 配置は 2 段のまま（ADR 0007・0009 の盤の大きさ）。大きな盤の画面は 93 × 30、縮小版は 75 × 22 が要る
4. **枠は 2 種類**: 罫線（既定）と ASCII。起動時に合成ルートが `─` を 1 文字書いてカーソル位置を問い合わせ、1 桁進んだときだけ罫線を使う。
   2 桁進んだか、0.3 秒以内に答えが無ければ ASCII（`+-|#->`）。画面の文字は、枠と棒グラフの字形（`FrameGlyphs`）を除いて ASCII のまま
5. **テーマは 12 種類**（Gambit と同じ名前・順・11 色）。リバーシ用に足したもの:
   - 直前の手の印の色（12 色目）。PAPER だけ濃い青（#004A9A）、他は強調の色と同じ
   - **黒石は 2 色のうち暗いほう**。PAPER だけ 2 色を入れ替えた（黒石＝墨・白石＝赤）
6. `t` で次のテーマへ（最後の次は最初）、`--theme <名前>`（大文字小文字を区別しない）で起動時に選ぶ。持ち主は合成ルートの `DisplayOptions`

## 強制

- テスト（`make check` の `test` 段）: 12 テーマ × 2 つの配置 × 対局中と終局後で、英字・数字と盤の上の `[ ]` が前景と背景に対して 4.5:1 以上。
  石が 2 色の升に対して 3:1 以上、白黒の石どうしが 2.2:1 以上、**黒石の輝度が白石より低い**。枠の罫線と飾りの記号は控えめな色で描く設計なので対象にしない（Gambit と同じ）。
  ASCII の枠では画面の文字がすべて ASCII、罫線の枠でも ASCII 以外は枠の字形だけ。HUD の各段・LOG のカーソル・テーマの巡り方
- `make smoke`: `t` で PHOSPHOR に替わる・問い合わせに答えない疑似端末では ASCII の枠（`+-[ MATCH ]`）に落ちる
- **planned**: 罫線が 1 桁で描かれる端末で罫線が選ばれることは疑似端末では見られない。Windows Terminal の画面写真で確かめた（下）

## 結果

- 実機（2026-10-26・Windows Terminal）で NEON・PAPER・SYNTHWAVE の大きな盤と NEON の縮小版を撮った。罫線の枠が選ばれ、HUD は Gambit と同じ形に描かれた。
  PAPER の白石が黒く見えることはこの写真で見つけ、入れ替えた
- 失うもの: 画面の部品と Render の型が増えた。棒グラフのブロック（`█░▌`）は罫線と同じ問い合わせの結果で選ぶので、罫線だけが 1 桁でブロックが 2 桁の端末があれば崩れる（Gambit と同じ前提）
- COMMS の 2 行はまだ空（次の Issue でキャストの顔とセリフを入れる）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 罫線を無条件に使う | 幅が 2 桁の端末で盤と HUD が崩れる |
| ASCII の枠だけにする | 施主の決定（FR-16 の B 案の罫線の枠）と違う |
| Gambit の PAPER の駒の色をそのまま当てる | 白石が墨色で黒く見える。リバーシでは石の色が意味そのもの |
| PAPER の升を暗くして白石を白くする | 白石・黒石・直前の手の印の 3 つを 1 つの升の色で同時に足りるコントラストにできなかった（白が 3:1 に届く暗さでは印が 4.5:1 に届かない） |
| `[ ]` を文字の色で描く | Gambit の強調の色の印の見た目が消える。足りないのは PAPER だけなので、そこだけ色を足した |
