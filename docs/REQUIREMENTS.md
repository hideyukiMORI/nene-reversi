# 要件と施主の決定 — NeNe Reversi

> Status: normative（規範）/ 2026-10-26 初版
> 施主（hide）が言ったこと・決めたことだけを書く。**施主が言っていない機能を要件に書かない・実装しない。**
> 施主から後で違う指示が来たら、それに従って変え、ADR で置き換える。

NeNe Reversi は、WSL2 の Ubuntu の端末（Windows Terminal）で、黒と白の手作りのリバーシ AI が延々と打ち続けるスクリーンセーバーである（Swift 製）。
1 局が終わったら次の局を始め、`q` を押すまで続く。チェス版の兄弟 [NeNe Gambit](https://github.com/hideyukiMORI/nene-gambit) と同じ形
（サイバー HUD・12 テーマ・4 名のキャストの減らず口・終局後の秒読み・`install.sh` の 1 行で入る配布）を、リバーシで、新しいキャストで作る。
スクリーンセーバーに要るのは強さではなく「見ていて飽きない対局」である。

## 1. 要件（FR）

FR の番号は Gambit とそろえた（FR-12 は Gambit の 12 テーマの引き継ぎ）。

| ID | 要件 |
| --- | --- |
| FR-01 | 端末に盤面を描き、黒と白の AI が 1 手ずつ交互に打つ様子を見せる（リバーシは黒が先手） |
| FR-02 | 合法手の生成と石の反転を完全に扱う: 8 方向の挟み・複数方向の同時反転・打てる手が無いときのパス・両者とも打てないときの終局。perft で公表値と一致することをゲートで確かめる |
| FR-03 | AI は評価関数＋アルファベータ探索で手を選ぶ |
| FR-04 | 終局判定: 両者とも打てない（盤が埋まった場合を含む）。石の数で勝ち・負け・引き分けを決め、結果を見せ、次の局を自動で始める |
| FR-05 | 毎回違う対局になる（序盤の数手をランダムにする・評価が同点の手から乱数で選ぶ） |
| FR-06 | 黒と白で強さや性格を変えられる（探索の深さ・評価の重み）。勝ち負けにばらつきを出す |
| FR-07 | 石は文字ではなく、升とは別の色で塗ったブロックで描く（幅は偶数桁）。黒石と白石の色はテーマが決める。字形を使わないので、表示の切り替えは無い |
| FR-08 | `q` で終了する。どんな終わり方でも端末を必ず元に戻す |
| FR-09 | 動作環境: WSL2 の Ubuntu＋Windows Terminal |
| FR-10 | 盤の横（HUD）に、直近の棋譜数手・通算の勝敗（黒勝ち / 白勝ち / 引き分け）と局数・手番と手数・黒白の性格名・現在の石の数（黒 n・白 n）を出す |
| FR-11 | 1 手の間隔の初期値は 1.0 秒・終局後に結果を見せる時間の初期値は 3 秒。起動オプションで変えられる |
| FR-12 | 12 テーマは Gambit の 12 種類（名前と配色の方針）を引き継ぎ、盤と石の色をリバーシ用に足す |
| FR-13 | カラーテーマは 12 種類くらい。実行中のキー（`t`）で切り替え、起動時は `--theme <名前>` で選ぶ |
| FR-14 | 対局中に各キャラクターが感想やリアクションを言う。英語で、ウィットに富んだブラック、ニヤッとしてしまうもの。キャストは 4 名（性格）で、局ごとにランダムに組む。セリフは 1 人 50 本。キャストは Gambit とは別の新しい 4 名 |
| FR-15 | キーのヘルプを画面のどこかに常に出す |
| FR-16 | 画面は Gambit の B 案（罫線の枠）と同じ構成。直前の手は、打った石の升を `[ ]` で囲む・端末の大きさで 2 段の配置・終局後は次の局までの秒読み。罫線が 2 桁で描かれる端末では自動で ASCII の枠に落とす |

## 2. 施主の決定（2026-10-25）

施主の言葉: 「全部リナの推しでいいよ。気になったら後で指示するから。」これで Q4〜Q10 は実装側の推しで決定した。

| # | 論点 | 状態 |
| --- | --- | --- |
| Q1 | アプリ名 | 決定: NeNe Reversi（`nene-reversi`）。登録商標のボードゲームの商品名は、製品名・README・コード・セリフのどこにも書かない。ゲームの名前は「Reversi / リバーシ」と書く（CNF-023 が機械で見る） |
| Q2 | 公開範囲とライセンス | 決定: PUBLIC・MIT |
| Q3 | 中身 | 決定: Gambit と同じ形（スクリーンセーバー・サイバー HUD・テーマ・キャストの減らず口）・新しいキャスト。リバーシの AI は外部のエンジン・ライブラリを使わず一から書く（Gambit の方針の引き継ぎ。変えたくなったら施主に聞く） |
| Q4 | 石の表示 | 決定（推し）: 升の背景とは別の色で塗った偶数桁のブロック。表示の切り替えは無い（FR-07）。実機の画面写真で確かめてから施主に見せる |
| Q5 | 直前の手の示し方 | 決定（推し）: 打った石の升を `[ ]` で囲む。ひっくり返った石の強調などは足さない |
| Q6 | HUD に現在の石の数を出すか | 決定（推し）: 出す（FR-10） |
| Q7 | 新しいキャスト 4 名の名前・性格・指し方 | 決定（推し）: 実装側が決める。Gambit の 4 名とは違う名前・違う性格にし、`ファイル名.拡張子` 風の名前と顔文字という作法はそろえる。指し方の違い（深さ・評価の重み）と勝敗のばらつきは計測して ADR に書き、決めたら施主に知らせる |
| Q8 | テーマの中身 | 決定（推し）: Gambit の 12 テーマを引き継ぎ、盤と石の色を足す（FR-12）。コントラストの検査は機械で行う |
| Q9 | `q`・`t` 以外の操作 | 決定（推し）: 足さない。キーは `q`（終了）と `t`（テーマ）だけ |
| Q10 | 遊び心（裁量の演出） | 決定（推し）: FR に書いたもの以外の演出は足さない。思いついたら施主に提案する |
| Q11 | 道具の導入 | 決定: 開発用の道具は確認を待たずに入れてよい。製品の依存は CODING_RULES 第 5 節の 3 点で管理する |
| Q12 | 進め方 | 決定: フルゲートが緑なら、Ready・squash merge・Issue の起票は確認なしでよい。Release の公開など外に出る操作は確認を取る |

## 3. やらないこと

- 施主が言っていない機能（人間が AI と対局する機能を含む）
- 外部のリバーシエンジン・ライブラリを使うこと
- perft の期待値を記憶で書くこと・ゲートで回す深さを黙って下げること
